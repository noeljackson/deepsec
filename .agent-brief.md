## What to build

### 1. The agent loop

`cmd/benchsec agent` (or `cmd/benchsec autopatch` — your call). One
iteration is:

1. **Pick a target slug.** Use the existing per-slug FP/FN dashboard.
   The default policy is "worst-precision slug among those with > 1 FP";
   accept `--slug` to override.
2. **Compile context.** Top N false positives (file, line, snippet,
   matched fragment) and top M false negatives (answer-key entry,
   closest candidate if any) for the target slug.
3. **Ask the model for one bounded patch.** Use the `zai-coding`
   profile by default (subscription, cheap). The prompt instructs the
   model to choose exactly one of:
   - Add a `suppress_pattern` to silence one FP without losing TPs.
   - Add a `require_content` precondition.
   - Tighten `file_patterns`.
   - Add a `requires.tech` gate.
   - Output `{"decision": "needs-engine-feature", "reason": "..."}` if
     no TOML change can fix it.
4. **Apply the patch.** Edit the bundled matcher TOML in place. Stage
   nothing yet.
5. **Verify the diff is in-scope.** Reject patches that touch any
   field outside the allow-list above, touch any non-matcher file, or
   delete the entire matcher.
6. **Score.** Run the scanner scorer on a fresh temp `DataRoot`,
   captured for the affected slug only.
7. **Gate.** Accept iff every Pareto check passes:
   - Target slug's precision didn't drop.
   - Target slug's recall didn't drop.
   - **No** other slug's recall dropped by more than 0% on
     HIGH/CRITICAL issues.
   - **No** other slug's precision dropped by more than 5%.
   - `go test ./...` still passes (skip the known CLI e2e flakes).
   - Total candidate count didn't grow by more than a configured
     budget (default 5% relative).
8. **Capture provenance.** On accept: append a regression case for
   every FP that disappeared and every FN that got resolved (use the
   format from #15). Write an `AGENT_DECISIONS.md` line describing the
   patch, the slug, the gate result, and a model-provided rationale.
9. **Commit or revert.** Accept → commit with a message like
   `agent(<slug>): <rationale-summary>`. Reject → revert the matcher
   TOML, no commit, log the rejection.

### 2. Safety rails

- **Dry-run by default.** `--apply` is required for the loop to
  actually commit. Without it, every iteration prints the proposed
  patch + gate result and exits without writing.
- **`--max-iterations N`** (default 1). The agent runs at most N
  accepted patches per invocation. Each iteration is an independent
  commit.
- **`--max-cost-usd X`** (subscription billing reports $0, but pass
  through for safety with a real backend).
- **Clean git tree required.** Refuse to run if `git status --porcelain`
  is non-empty. We don't want the agent's commits tangled with the
  human's WIP.
- **`--held-out <task-id,...>`** — exclude these tasks from the gating
  score *and* from the FP/FN context shown to the model, so they truly
  test generalization. Run the held-out scorer at the end of the
  session and print the delta.
- **Cap consecutive rejections.** If `--max-rejections 3` consecutive
  proposals get rejected, halt the loop. Loud failure beats wasted
  cycles.
- **Refusal envelope.** If the model returns `needs-engine-feature`,
  log it to `AGENT_DECISIONS.md` as a human-review item and skip to
  the next slug.

### 3. LLM proposer integration

A new file `internal/processor/agent_proposer.go` (or under `cmd/benchsec/`):

- Function: `ProposePatch(ctx, backend, slug, fps, fns, currentMatcher string) (Patch, error)`
- Uses the existing `processor.AgentBackend` interface so any provider
  works. The default is `zai-coding`/`glm-5.1`.
- The prompt lives in `internal/processor/prompts/agent.md` (extend the
  externalised prompts pattern from #7).
- Returns a structured `Patch` value with one of: `SuppressPattern`,
  `RequireContent`, `FilePatterns`, `RequiresTech`, or
  `NeedsEngineFeature`.
- Strict schema parsing — anything else is a rejection.

### 4. AGENT_DECISIONS.md

A single append-only file at the repo root. One entry per agent
invocation:

```markdown
## 2026-05-13T12:34Z — slug=flask-route — accepted
- Patch: added `require_content = ["request\\."]` to scope to handlers
  that use the request object.
- FPs resolved: 4 (in py-vulnerable-flask app.py:15,20,30,35)
- FNs introduced: 0
- Regression cases added: 4
- Provider: zai-coding / glm-5.1
- Commit: abc1234
```

```markdown
## 2026-05-13T12:35Z — slug=sql-injection-string-concat — rejected
- Patch: tightened `file_patterns`
- Reason: HIGH recall on bench/tasks/ts-vulnerable-app dropped (1 → 0)
- No commit; file reverted.
```

The file is the project's running log of autonomous changes — a human
should be able to skim it and understand what the agent has been
doing.

### 5. Tests

- **Proposer test** with a mock `AgentBackend` that returns a known
  patch; verify it parses, applies, and the gate runs.
- **Gate test** with a synthetic FP/FN delta that should accept; with
  one that should reject because another slug regressed.
- **Dry-run test**: same invocation with and without `--apply` —
  without `--apply`, the matcher TOML must be unchanged on disk after
  the run.
- **Held-out test**: the held-out task's score is computed separately
  and printed, but does not feed into gating decisions.

## Out of scope

- Processor-prompt optimization (separate phase). Matchers only.
- Multi-slug patches. One slug per iteration.
- Engine features. The agent must defer to a human via
  `needs-engine-feature`.
- Live recording of real processor fixtures (already done in #13).

## Constraints

- New code under `cmd/benchsec/`, `bench/`, or
  `internal/processor/agent_proposer.go`.
- No new third-party deps.
- The agent must not modify any file outside
  `internal/scanner/matchers/*.toml` and
  `internal/scanner/regression_cases.toml`, ever — verify in code
  before applying any patch.
- Path safety on every disk write.
- Go 1.25.10, `go test ./...` green, `go vet ./...` clean.
- Net new lines under ~2000.

## Acceptance criteria

1. `go build ./...`, `go vet ./...`, `go test ./bench/...
   ./cmd/benchsec/... ./internal/processor/... ./internal/scanner/...`
   green.
2. `benchsec agent --slug flask-route` (dry-run, no LLM call, with a
   mock proposer) produces a patch preview and gate result.
3. `benchsec agent --slug flask-route --apply --max-iterations 1`
   (still with mock proposer) makes exactly one commit if the gate
   passes.
4. `AGENT_DECISIONS.md` is appended to and never overwritten.
5. The dry-run / `--apply` test passes.
